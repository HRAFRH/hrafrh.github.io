Finding where a LiDAR proximity pipeline was delayed

Sensor output, autopilot input and the ground-station display needed to be examined separately.

Achraf RAHIBE · Project retrospective

The challenge: a delayed display is not a diagnosis

The integration connected a Unitree L2 LiDAR pipeline to ArduPilot through companion computing. Proximity information appeared delayed, but the visible symptom alone could not establish whether the delay came from sensing, transport, autopilot input or display rendering.

Trace the data path

I reviewed the ROS 2 and MAVROS path into MAVLink OBSTACLE_DISTANCE, together with serial mapping and proximity settings. I separated sensor-to-autopilot latency from ground-station rendering and proposed ground checks to examine the interfaces and timing.

An actionable investigation

The output was an integration findings report with validation steps. It narrowed the questions for the next checks instead of treating an unverified tuning change as a complete solution. The public report excerpts show the approach; universal obstacle-avoidance performance is not claimed.
